# The Codex plugin

`codex-plugin/` is a generated mirror of `plugin/`, carrying the same nine skills to Codex. It is
regenerated by `scripts/build_codex_plugin.py`, and checked by
`tests/plugin/test_codex_plugin.py`, by `ci.yml` and by `release.yml`, so it cannot drift from the
authored copy under `plugin/skills/`. A workflow only ever checks: a repair inside the release run
would ride into the version-bump commit unreviewed.

## Install

```bash
# from a checkout
codex plugin install ./codex-plugin

# the MCP server on its own, without the plugin
codex mcp add auditor -- uvx --python 3.13 --from 'auditr[mcp,observer-codex]' auditr-mcp
```

## What is in it

- `.codex-plugin/plugin.json`: the manifest. `skills` and `mcpServers` point at siblings of
  `.codex-plugin/`, because paths inside the manifest resolve from the plugin root.
- `.mcp.json`: the `auditor` MCP server,
  `uvx --python 3.13 --from 'auditr[mcp,observer-codex]' auditr-mcp`.
  Both extras: the graph tools need `mcp`, and a Codex session that drives a refinement needs the
  runner. The first `uvx` resolve downloads the Codex SDK's bundled binary, which is large.
- `skills/`: the nine skills, `references/` trees included.

## What is deliberately not in it

- **No `hooks` key.** Codex documents one and does not load it. The observer's two hooks are a
  `~/.codex/hooks.json` copy instead, in [observer.md](observer.md).
- **No `agents`.** Codex loads no plugin-declared agents, so `judge-findings` mirrors across but
  loses its `auditor-reviewer` dispatch and runs inline.
- **No statusline.** Codex has no equivalent surface.

Codex's skill parser keeps `name`, `description` and `metadata.short-description` and silently
drops everything else, so the `paths:` globs on four skills and the `context: fork` on
`judge-findings` are inert rather than broken.

## Regenerating it

```bash
uv run python scripts/build_codex_plugin.py            # write
uv run python scripts/build_codex_plugin.py --check    # report drift, exit 1 if any
```
